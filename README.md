Бінарна класифікація з максимізацією Balanced Accuracy

Розв'язання задачі бінарної класифікації на незбалансованому табличному датасеті (телеком-стиль, ~13% позитивного класу) з фокусом на balanced accuracy як цільову метрику. Фінальна модель — зважений ансамбль XGBoost + CatBoost з таргет-кодуванням категорій, автоматизованим підбором гіперпараметрів (Optuna) та чесною (nested cross-validation) оцінкою якості. Результат
Метрика	Значення
Balanced accuracy (чесна, nested CV, 10 фолдів)	0.9052 ± 0.0079
Оптимальний поріг класифікації	0.449 ± 0.044
Модель	Зважений блендинг XGBoost (вага 0.40) + CatBoost (вага 0.60)

Увесь тюнінг (гіперпараметри, кодування, відбір ознак, поріг) підбирався на тренувальних даних. Щоб уникнути оптимістичного зміщення, фінальна метрика розрахована через вкладену (nested) крос-валідацію: для кожного із 10 зовнішніх фолдів кодування категорій і поріг перераховуються окремо, без жодного витоку інформації з валідаційної частини.

Датасет
10 000 тренувальних об'єктів, 2 500 валідаційних (без міток)
230 анонімізованих ознак: Var1–Var190 (числові), Var191–Var230 (категоріальні)
Сильний дисбаланс класів (~87% / ~13%)
Значна частка пропущених значень у числових ознаках (від 0% до 100% по колонках)
Категоріальні ознаки різної кардинальності — від 2 до понад 5000 унікальних значень
Методологія
Обробка даних
Видалено колонки зі 100% пропусків або єдиним унікальним значенням
Індикатори пропусків (_isna) додано як окремі бінарні ознаки для колонок з частковою пропущеністю
Target encoding (OOF, K-fold, зі згладжуванням) для high-cardinality категоріальних ознак; для CatBoost — нативна обробка категорій і пропусків (NaN без імпутації) замість ручного кодування
Відбір ознак
Permutation importance, усереднена по 5 незалежних 70/30-спліт — надійніша за gain-based важливість з одного фіту моделі
Фінальний набір: 40 ознак (з ~400 після базового очищення)
Моделі та гіперпараметри
XGBoost — гіперпараметри підібрані Optuna з кастомним scorer'ом (balanced accuracy при оптимальному порозі, а не при порозі 0.5 за замовчуванням)
CatBoost — окремий Optuna-тюнінг гіперпараметрів, нативна обробка NaN і категоріальних ознак
Балансування класів через scale_pos_weight / auto_class_weights='Balanced' (без oversampling/SMOTE — ручний random oversampling перевірявся, ефекту не дав)
Поріг класифікації
Balanced accuracy = (Sensitivity + Specificity) / 2 — сильно залежить від порогу при дисбалансі класів. Поріг підбирається через перебір сітки, усереднений по 5 незалежних CV-розбиттях для стабільності (робастний поріг)
Той самий принцип застосовано і до блендингу, і до соло-моделей — усунуто методологічну нерівність, знайдену на попередніх ітераціях
Валідація
Nested cross-validation (5 фолдів × 2 повтори = 10 зовнішніх фолдів) — кодування й поріг перераховуються окремо в кожному фолді, без витоку інформації
✅ Що спрацювало / ❌ що не дало приросту
Підхід	Результат
Кастомний scorer (BA@оптимальний поріг) для Optuna	✅ Найбільший приріст
Multi-split permutation importance	✅ Невеликий, стабільний приріст
Спільний Optuna-пошук smoothing + гіперпараметрів	❌ Не перевершив послідовний підбір
Optuna-тюнінг гіперпараметрів CatBoost	✅ Реальний приріст
Блендинг XGBoost + CatBoost (робастний поріг)	✅ Кращий за будь-яку соло-модель
Quantile bins / ranks для топ-ознак	❌ Погіршення
Калібрування ймовірностей (isotonic, sigmoid/Platt)	❌ Жодне не перевершило "сирі" ймовірності
Ручний random oversampling мінорного класу	❌ Без ефекту

Ноутбук виконується послідовно, клітинка за клітинкою. Повний прогін (з Optuna-пошуком і nested CV) займає орієнтовно 30–60 хвилин залежно від потужності машини. Щоб пропустити дорогий пошук і одразу відтворити фінальну модель — завантажте best_config.json і підставте збережені гіперпараметри/ознаки напряму в конструктори моделей (детальніше — у розділі "Заморозка конфігурації" ноутбука).

Заморозка переможної конфігурації (best_config.json)

Псевдо-мітки (semi-supervised) на основі впевнених прогнозів на валідаційному наборі

Повністю вкладений (nested) відбір ознак і гіперпараметрів — усуне залишкове оптимістичне зміщення ціною ~10-кратного збільшення часу обчислень
Відомі обмеження
sklearn.clone() несумісний з CatBoostClassifier(cat_features=...) — там, де потрібне клонування моделі (cross_val_predict тощо), використовується ручна реалізація K-fold циклу замість стандартних sklearn-утиліт
Пошук гіперпараметрів і відбір ознак не повторюються всередині кожного зовнішнього фолду nested CV (обчислювально занадто дорого) — залишкове, менше за основне, джерело оптимістичного зміщення оцінки
